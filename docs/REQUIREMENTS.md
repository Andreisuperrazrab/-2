# Вимоги й критерії приймання · Bounty Hunter

**Підстава:** завдання ЛР №5 «Розроблення вебзастосунку з використанням технологій вайбкодингу», одержаний вихідний архів `bounty-hunter.zip` (HTML/CSS/JS). Первинні індивідуальні звіти/макети ПР №1–2 одногруппника не передані; їхню відповідність треба підтвердити окремо.

| ID | Вимога (Must) | Критерій приймання | Реалізація / перевірка |
|---|---|---|---|
| FR-01 | Реєстрація й автентифікація | Реєстрація створює запис users; неправильний пароль → 401; вихід відкликає сесію | `/api/auth/*`, API test 3 |
| FR-02 | Каталог фрилансерів | Виведення з БД; фільтри category, level, availability, rating, search | `/api/freelancers`, API test 2, DOM скрин №2 |
| FR-03 | Профіль фрилансера | GET за id; PATCH тільки власного профілю | `/api/profile/me`, API test 6 |
| FR-04 | CRUD вакансій | Створення/оновлення/видалення лише власником з роллю client; читання для всіх | `/api/jobs`, API test 4 |
| FR-05 | Подача заявки | Тільки freelancer; одна заявка на (job_id, applicant_id); дані зберігаються | `/api/jobs/:id/applications`, API test 5 |
| FR-06 | Статус заявки | Автор заявки читає власну; замовник вакансії змінює статус | `/api/applications/*`, API test 5 |
| FR-07 | Чат | Повідомлення зберігаються в messages; історію бачать лише двоє учасників | `/api/messages`, API test 7 |
| FR-08 | Підтримка | Звернення в БД, без необґрунтованої обіцянки відповіді | `/api/support`, API test 7 |
| NFR-01 | Доступність | Семантика, одне h1/сторінка, коректні label/for, alt, фокус, мобільне компонування | `tests/static_audit.py`, DOM-симуляція |
| NFR-02 | Захист даних | `scrypt`, HttpOnly, SameSite, контроль Origin, ролі, параметризовані SQL, CSP | API tests 3–9 |
| NFR-03 | Продуктивність | Обробка 200 GET `/api/jobs` із 10 паралельними клієнтами без помилок | `docs/performance.json` (локально) |
| NFR-04 | Репозиторій і відтворюваність | Системні залежності описано; `npm start` і `npm test`; Dockerfile | README, 9 API-тестів |
| NFR-05 | Розгортання | Docker запуск, постійний том SQLite, HTTPS, контроль /api/health | `Dockerfile`, `compose.yaml`, `docs/DEPLOY.md`; зовнішній деплой очікує облікового запису |

**Виконано як MVP:** клієнт, сервер, SQLite, REST API, CRUD, застосування Fetch API та async/await, робочі форми, перевірки безпеки. **Не підтверджено:** збіг з індивідуальною специфікацією ПР №1/2, публічний URL і GitHub одногруппника, повноцінний реальний браузерний тест на хостингу.
