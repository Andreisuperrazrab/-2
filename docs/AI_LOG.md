# Журнал взаємодії зі ШІ та критична перевірка результатів

**Використаний інструмент:** ChatGPT (GPT-6). **Дата роботи:** 23.11.2026. **Матеріали:** `bounty-hunter.zip` (11 HTML-сторінок, 4 CSS-файли, 1 JS-файл), `Лабораторна_робота_5 (1).docx`. Цей журнал містить **реальні етапи та стислий зміст відповідей**, а не вигадані повні транскрипти розмови.

## P0. Початкове звернення користувача

**Фактичні повідомлення користувача (російською):** «Так эта работа одногруппника надо ему максимально помочь ... проанализируй и выполнит данную работу ...»; уточнення: «Лабораторную номер 5 надо выполнить».

**Результат аналізу:** визначено, що Bounty Hunter вже має 11 HTML-сторінок, файли CSS і `js/main.js`, але дані `FREELANCERS`/`JOBS` захардкоджені в JavaScript, логін зберігається у `sessionStorage`, подання заявки та повідомлення не звертаються до сервера. Обрано продовження наявного дизайну, а не заміну теми.

## P1. Формалізований промпт на архітектуру (специфікація для ШІ)

> На основі наданого фронтенду Bounty Hunter та вимог ЛР №5 запроєктуй Node.js вебзастосунок із JSON REST API, SQLite БД, автентифікацією, CRUD вакансій, профілями фрилансерів, заявками й чатом. Збережи наявну HTML/CSS-структуру. Визнач ролі й дозволи, структуру БД, ризики та критерії приймання. Не вигадуй URL деплою та репозиторію.

**Зміст відповіді/реалізації ШІ:** розділено `public/`, `server/app.js`, `server/db.js`; заплановано 7 таблиць, REST маршрути, cookie-сесії та ролі `freelancer` і `client`; модель приймання за функціональними й нефункціональними вимогами в `REQUIREMENTS.md`.

**Критична перевірка:** навмисно не впроваджено платежів і фіктивної відповіді оператора; початкові Figma-джерела та індивідуальна специфікація одногруппника не надані, тому їх відповідність поки не підтверджена.

## P2. Формалізований промпт на код і безпеку

> Реалізуй REST API так, щоб пароль не зберігався відкритим текстом, неавторизовані користувачі не могли змінювати вакансії, власники не могли змінювати чужі записи, SQL-запити були параметризованими, а DOM не вставляв user-generated HTML. Забезпеч постійне збереження заявок і чату після перезавантаження.

**Зміст відповіді/реалізації ШІ:** `scrypt` із сіллю, token hash у `sessions`, HttpOnly cookie, SameSite, перевірка Origin, role/owner check, SQLite `FOREIGN KEY` та `UNIQUE`, CSP, ліміти JSON, безпечна DOM-вставка через `textContent`, 13 HTML-сторінок включно з двома доданими (`profile.html`, `applications.html`).

**Уточнення/компроміс:** у модулі Node 22 `node:sqlite` є попередження `ExperimentalWarning`, але він працює у наданому середовищі і не потребує npm registry. Express не використано: стандартний HTTP-маршрутизатор реалізовано самостійно. В окремому середовищі з доступом до npm можна перенести маршрути на Express без зміни контрактів API.

## P3. Формалізований промпт на перевірку

> Зроби перевірки реальних HTTP-запитів та виявляй щонайменше: неправильний логін, дублікати, незаконний CRUD чужих вакансій, повторну заявку, несанкціонований доступ до заявок, приватність чату, небезпечні Origin, занадто великий JSON, проблемні мітки форм і мобільне переповнення. Виправ знайдені помилки.

**Отримані результати:** 9/9 груп автоматичних API-тестів пройдено (`tests/api.test.js`); 13 HTML-сторінок, 35 полів з відповідними підписами, 0 битих локальних посилань (`tests/static_audit.py`); 200 GET із 10 паралельними клієнтами, 0 помилок (`docs/performance.json`).

**Знайдені й виправлені недоліки:**

- Сторінка чату не мала `h1` → додано семантичний заголовок, прихований лише візуально.
- Атрибут `hidden` міг бути перекритий `.btn {display:inline-flex}` → додано `[hidden] {display:none!important}`.
- Контраст допоміжного тексту та акцентного кольору був слабким → кольори скориговано в `tokens.css`.
- Зовнішній Google Fonts вимагав мережі → підключення прибрано, залишено system-font fallback.
- Неправдиві автоматичні відповіді чату й підтримки з попередньої версії → прибрано; зберігаються лише реальні повідомлення/звернення.

## P4. Формалізований промпт на браузер і деплой

> Перевір відображення сценаріїв у Chromium, на десктопі й мобільному пристрої; підготуй Dockerfile та інструкцію публікації на хостингу з постійним диском. Не називай неперевірене розгортання успішним.

**Результат:** прямий перехід Chromium за локальними HTTP URL блокувався `ERR_BLOCKED_BY_ADMINISTRATOR`. Виконано альтернативну DOM-перевірку в Chromium: завантажено ті самі HTML, CSS та JS, а HTTP-запити проксійовано до реального локального API. Перевірено 9 екранів і 35 API-звернень, 0 JS pageerror і 0 горизонтального переповнення на 390 px. **Це не замінює реальний E2E/хмарний браузерний тест**, що залишено як обов'язковий крок власника.

**Публікація:** створено Dockerfile та `compose.yaml`, описано Railway/Render. Зовнішній deploy і GitHub push не виконувалися через відсутність облікових даних одногруппника; відповідні URL в звіті залишені незаповненими.

## Висновок щодо використання ШІ

ШІ пришвидшив архітектуру, генерацію коду, тестів і звіту. Відповідальність за приймання, перевірку публічного сайту, зіставлення з попередніми лабораторними роботами та дотримання академічної доброчесності залишається за студентом. Результати автоматичних тестів не доводять відсутності всіх вразливостей або повної відповідності WCAG.
